📋 Vad handlar den här fasen om?

Multi-tenancy är borttaget. Det kräver grundläggande omskrivning av hela datalagret och är inte relevant för ett utbildningsprojekt.

Redis och Celery är borttagna — löst enklare i Fas 2.

Allt som finns kvar här är additivt — vi bryter ingenting som redan fungerar.

📈 Steg 1 — Prometheus metrics

Vad tillför det?

En /metrics-endpoint som exporterar data om hur appen mår — antal requests, svarstider, felfrekvens. Prometheus är industristandard för monitoring och lätt att lägga till. Det är ett bra första steg i Fas 3 eftersom det inte ändrar något befintligt.

Ny fil: src/monitoring.py

from prometheus_client import Counter, Histogram, generate_latest, CONTENT_TYPE_LATEST
from flask import Response

# Räknare och histogram för HTTP-requests
REQUEST_COUNT = Counter(
    "http_requests_total",
    "Totalt antal HTTP-requests",
    ["method", "endpoint", "status"]
)
REQUEST_LATENCY = Histogram(
    "http_request_duration_seconds",
    "Svarstid per request i sekunder",
    ["endpoint"]
)

def setup_metrics(app):
    """Registrera metrics-endpoint och middleware på Flask-appen."""
    
    import time
    from flask import g, request

    @app.before_request
    def start_timer():
        g.metrics_start = time.time()

    @app.after_request
    def record_metrics(response):
        # Hoppa över metrics-endpointen själv
        if request.path == "/metrics":
            return response
        elapsed = time.time() - g.get("metrics_start", time.time())
        REQUEST_COUNT.labels(request.method, request.path, response.status_code).inc()
        REQUEST_LATENCY.labels(request.path).observe(elapsed)
        return response

    @app.route("/metrics")
    def metrics():
        return Response(generate_latest(), mimetype=CONTENT_TYPE_LATEST)

Aktivera i src/app.py

from monitoring import setup_metrics

# Lägg till efter att Swagger är initialiserat
setup_metrics(app)

Testa direkt

Starta appen och besök http://localhost:8080/metrics. Gör några API-anrop och ladda om — räknarna ökar. Det är allt Prometheus behöver för att kunna scrapa datan.

🔗 Steg 2 — GraphQL som alternativt API

Vad tillför det?

REST API:et fungerar utmärkt och ändras inte. GraphQL läggs till som ett alternativt sätt att fråga data — på en separat endpoint /graphql. Det är ett bra tillfälle att lära sig hur GraphQL fungerar i ett Flask-sammanhang utan att riskera det befintliga REST-lagret.

Ny fil: src/graphql_schema.py

import graphene
from database import get_db

# Definiera GraphQL-typen för en guestbook-post
class GuestbookEntry(graphene.ObjectType):
    user_id = graphene.Int()
    name = graphene.String()
    email = graphene.String()
    comment = graphene.String()
    created_at = graphene.String()

# Query-klassen definierar vilka frågor som är möjliga
class Query(graphene.ObjectType):
    entries = graphene.List(
        GuestbookEntry,
        limit=graphene.Int(default_value=10),
        search=graphene.String()
    )
    entry = graphene.Field(GuestbookEntry, user_id=graphene.Int(required=True))

    def resolve_entries(self, info, limit=10, search=None):
        conn = get_db()
        if search:
            rows = conn.execute(
                "SELECT * FROM guestbook WHERE name LIKE ? LIMIT ?",
                (f"%{search}%", limit)
            ).fetchall()
        else:
            rows = conn.execute("SELECT * FROM guestbook LIMIT ?", (limit,)).fetchall()
        conn.close()
        return [GuestbookEntry(**dict(r)) for r in rows]

    def resolve_entry(self, info, user_id):
        conn = get_db()
        row = conn.execute("SELECT * FROM guestbook WHERE userId = ?", (user_id,)).fetchone()
        conn.close()
        return GuestbookEntry(**dict(row)) if row else None

schema = graphene.Schema(query=Query)

Registrera i src/app.py

from flask_graphql import GraphQLView
from graphql_schema import schema

# Lägg till GraphQL-endpoint
app.add_url_rule(
    "/graphql",
    view_func=GraphQLView.as_view("graphql", schema=schema, graphiql=True)
)

💡 GraphiQL — interaktivt verktyg

Besök http://localhost:8080/graphql i webbläsaren. Du får ett interaktivt verktyg för att skriva och köra GraphQL-frågor — liknande Swagger UI men för GraphQL.

🗄️ Steg 3 — PostgreSQL-migration (stort steg)

Vad tillför det och varför är det ett stort steg?

SQLite är perfekt för ett utbildningsprojekt — det är en fil, inga processer att starta. PostgreSQL är industristandard för produktionsdatabaser: bättre hantering av många simultana skrivningar, fullständiga ACID-transaktioner, bättre datatyper. Det här steget kräver att vi skriver om datalagret och sätter upp migreringar med Alembic. Gör det sist.

⚠️ Förutsättningar

PostgreSQL måste vara installerat och en databas skapad lokalt, eller kör det via Docker: docker run -p 5432:5432 -e POSTGRES_PASSWORD=test postgres:16.

Ta backup av guestbook.db innan du börjar.

Steg 3a — Konfigurera SQLAlchemy

# Ny fil: src/db_config.py
import os
from sqlalchemy import create_engine, text
from sqlalchemy.orm import sessionmaker, declarative_base

# Välj databas baserat på miljövariabel
# SQLite för lokal dev, PostgreSQL för produktion
DATABASE_URL = os.getenv(
    "DATABASE_URL",
    "sqlite:///data/guestbook.db" # Fallback till SQLite
)

engine = create_engine(DATABASE_URL)
Session = sessionmaker(bind=engine)
Base = declarative_base()

Steg 3b — Sätt upp Alembic för migreringar

# Kör i terminalen från projektets rot:
alembic init migrations

# Redigera migrations/env.py — peka på rätt Base och DATABASE_URL
# Sedan skapa första migrering:
alembic revision --autogenerate -m "initial schema"

# Applicera migreringen:
alembic upgrade head

Steg 3c — Migreringsscript för befintlig data

# scripts/migrate_sqlite_to_postgres.py
import sqlite3
import psycopg2

def migrate():
    sqlite = sqlite3.connect("data/guestbook.db")
    pg = psycopg2.connect("postgresql://user:pass@localhost/guestbook")
    
    rows = sqlite.execute("SELECT * FROM guestbook").fetchall()
    cursor = pg.cursor()
    for row in rows:
        cursor.execute(
            "INSERT INTO guestbook (name, email, comment, created_at) VALUES (%s, %s, %s, %s)",
            (row[1], row[2], row[3], row[4])
        )
    pg.commit()
    print(f"Migrerade {len(rows)} poster")

if __name__ == "__main__":
    migrate()

💡 Fördelen med DATABASE_URL-variabeln

Med DATABASE_URL som miljövariabel kan du köra SQLite lokalt under utveckling och PostgreSQL i CI/CD — utan att ändra en enda rad kod. Det är precis hur det fungerar i riktiga projekt.
