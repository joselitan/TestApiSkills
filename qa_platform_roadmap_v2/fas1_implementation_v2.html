🛡️ Steg 1 — Rate limiting på inloggning

Vad är problemet nu?

Just nu kan vem som helst försöka logga in hur många gånger som helst utan att bromsas. Det kallas brute force och är en grundläggande säkerhetsrisk. flask-limiter är redan installerat — vi behöver bara slå på det.

Fil att ändra: src/app.py

# Lägg till import högst upp i app.py
from flask_limiter import Limiter
from flask_limiter.util import get_remote_address

# Skapa limiter-objektet — lägg efter att app skapas
limiter = Limiter(
    app=app,
    key_func=get_remote_address,
    default_limits=["200 per day", "50 per hour"]
)

👥 Steg 2 — Rollkontroll (RBAC)

Vad är problemet nu?

JWT-tokenen innehåller redan ett role-fält (member eller admin). Men koden kontrollerar aldrig vilket roll användaren har — alla med giltig token kan göra allt. Vi behöver en enkel decorator som kontrollerar rollen.

Ny fil: src/auth_helpers.py — lägg till längst ner

def role_required(*allowed_roles):
    """Decorator som kräver en specifik roll i JWT-tokenen."""
    def decorator(f):
        @wraps(f)
        def decorated(*args, **kwargs):
            token = request.headers.get("Authorization")
            if not token:
                return jsonify({"message": "Token saknas"}), 401
            try:
                token = token.split()[1] if token.startswith("Bearer ") else token
                payload = jwt.decode(token, current_app.config["SECRET_KEY"], algorithms=["HS256"])
                user_role = payload.get("role", "member")
                if user_role not in allowed_roles:
                    return jsonify({"message": "Åtkomst nekad — fel roll"}), 403
            except Exception:
                return jsonify({"message": "Ogiltig token"}), 401
            return f(*args, **kwargs)
        return decorated
    return decorator

Hur används det i routes?

# Exempel: en admin-only cleanup-endpoint

    ...

📊 Steg 3 — Audit logging

Vad är problemet nu?

Loggern i logger_config.py loggar HTTP-requests men inte vad användaren faktiskt gjorde. Vi vill kunna se: vem loggade in, vem skapade en post, vem raderade något. Det är audit logging.

Ny fil: src/audit.py

import logging
from datetime import datetime
import jwt
from flask import request, current_app

# Skapa en separat logger bara för audit-händelser
audit_logger = logging.getLogger("audit")

def get_current_user():
    """Hämta användarnamn från JWT-token i requesten."""
    try:
        token = request.headers.get("Authorization", "")
        token = token.split()[1] if token.startswith("Bearer ") else token
        payload = jwt.decode(token, current_app.config["SECRET_KEY"], algorithms=["HS256"])
        return payload.get("user", "anonymous")
    except Exception:
        return "anonymous"

def log_action(action, resource, details=None):
    """
    Logga en användaråtgärd.
    Exempel: log_action("DELETE", "guestbook_entry", {"id": 5})
    """
    user = get_current_user()
    ip = request.remote_addr
    timestamp = datetime.utcnow().isoformat()
    msg = f"{timestamp} | USER={user} | IP={ip} | ACTION={action} | RESOURCE={resource}"
    if details:
        msg += f" | DETAILS={details}"
    audit_logger.info(msg)

Lägg till i logger_config.py — konfigurera audit-loggern

🔄 Steg 4 — Databastransaktioner på bulk-operationer

Vad är problemet nu?

I guestbook.py's bulk-delete och import-Excel körs SQL-satser utan explicit transaktionshantering. Om något går fel mitt i en bulk-radering kan databasen hamna i ett halvt raderat tillstånd. SQLite stöder transaktioner — vi behöver bara använda dem.

Ändra i src/blueprints/v1/guestbook.py

# Befintlig bulk_delete — lägg till try/except med rollback
def bulk_delete_entries():
    # ... validering ...
    conn = get_db()
    try:
        cursor = conn.cursor()
        placeholders = ",".join("?" * len(ids))
        cursor.execute(f"DELETE FROM guestbook WHERE userId IN ({placeholders})", ids)
        conn.commit() # Bekräfta bara om allt gick bra
        deleted = cursor.rowcount
    except Exception as e:
        conn.rollback() # Ångra om något gick fel
        return jsonify({"message": f"Fel: {str(e)}"}), 500
    finally:
        conn.close() # Stäng alltid anslutningen
    return jsonify({"deleted": deleted, ...})

💡 Samma mönster för import_excel

Wrap hela Excel-loopen i samma try/except/rollback-mönster. Om en rad i Excel-filen är ogiltig ska inga rader sparas alls.
